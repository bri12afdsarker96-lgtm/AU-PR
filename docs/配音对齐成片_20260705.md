# 配音对齐成片_20260705

## 一、功能目标

本轮新增“配音对齐成片”独立合成链路：消费水星音乐输出的配音包和水星剪辑已有的分镜视频目录，把每句分镜视频对齐到对应 WAV 的时长，替换为配音音轨后逐段拼接成片。该功能与现有 `assemble` 并行，不改变渲染差异化、指纹、重做、产线、回流和档案逻辑。

主入口：

```text
source/integrated_workbench/dub_sync.py
python -m source.integrated_workbench.cli dub-assemble --project <项目目录> --audio-dir <配音包目录> --video-dir <分镜视频目录>
```

UI 入口位于“剪辑与整合”页的“配音对齐成片”卡。

## 二、配音包协议

配音包为一个目录，内含：

- `配音清单.csv`，UTF-8-SIG 编码。
- 全部配音 WAV。

清单列：

```text
index,text,audio_file,duration_seconds,voice_id,engine
```

字段含义：

- `index`：1 起整数。
- `text`：该句文案原文。
- `audio_file`：WAV 文件名，相对配音包目录。
- `duration_seconds`：3 位小数。
- `voice_id`：音色库 ID，可空。
- `engine`：`real` 或 `mock`。

WAV 命名建议为 `{index:03d}_{安全化文案前8字}.wav`。消费方不依赖命名，只认清单；清单缺失时按 WAV 文件名自然排序兜底。协议版本变更需水星剪辑和水星音乐两侧文档同步登记。

## 三、对齐策略

所有时长以 FFprobe 实测为准，清单时长仅做交叉校验；清单时长与实测偏差超过 0.3 秒时，会在 `adjust_detail` 中记录。

三档处理：

- `as_is`：视频和配音时长差不超过 0.1 秒，保持原速并替换音轨。
- `trim_tail` / `trim_head` / `trim_center`：视频长于配音时裁剪到配音时长。默认 `head` 表示保留开头、裁尾。
- `slow`：视频短于配音，且差距不超过配音时长 15%，放慢视频到配音时长。
- `freeze`：视频短于配音，且差距超过配音时长 15%，原速播放后末帧定格补齐。

每段都会丢弃原视频音轨，并使用对应 WAV 作为唯一音轨。段文件统一转为项目剪辑尺寸、30fps、`setsar=1`、H.264/AAC 后再拼接。

## 四、产物与异常

产物目录：

```text
02_自动剪辑/07_配音成片/<成片名或配音成片_时间戳>/
```

目录内容：

- `<成片名>.mp4`
- `音画对齐表.csv`
- `音画对齐表.json`

对齐表记录 `DubSegment` 全字段、未匹配配音、未匹配视频和策略统计。配音数量与视频数量不一致时，多出的内容进入 `unmatched_audio` 或 `unmatched_video`，已有配对继续合成。单段失败会记为 `strategy=failed` 并跳过；成功段小于 1 时整体报错。

## 五、产线链路

CLI 完成后会提示：

```text
produce --source <成片>
```

也就是配音对齐成片可以直接作为矩阵产线输入，后续仍由现有产线负责差异化生成、指纹检测、高相似重做、合格待发布和回流模板。

v2026.07.04.4 起，UI 的“配音对齐成片”卡默认勾选“完成后直接一键生产”。勾选时，后台会先执行既有 `dub_assemble`，成功后把生成的成片作为 `source` 调用既有 `produce`；账号数和去重强度读取“矩阵生产”页当前值，页面尚未初始化时使用项目配置默认值。对齐成功但产线失败时不回滚成片，提示会给出成片路径并引导到“矩阵生产”页手动重试。

项目配置会记录上次成功使用的 `dub_last_audio_dir` 和 `dub_last_video_dir`，旧项目缺字段时按空值兼容，文件夹不存在时 UI 留空。

## 六、验收口径

业务流程验收新增“剪辑整合 | 配音对齐成片”项。验收工程程序化生成三段样例：

- 视频 3s + 配音 2s，预期 `trim_tail`。
- 视频 2s + 配音 2.2s，预期 `slow`。
- 视频 1s + 配音 2s，预期 `freeze`。

验收断言成片存在、总时长约等于三段配音时长之和、三段策略正确、成片包含音频流，并额外构造无清单配音包验证 WAV 文件名自然排序兜底。
